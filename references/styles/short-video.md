# 短视频口播风格

## 适用范围

用于把文章、观点、课程片段或方法论改写成 60-180 秒、可以直接朗读的知识型短视频口播。适合视频号、抖音、小红书等竖屏视频的旁白或真人出镜讲述。

这是一种叙事和表达风格，不代表必须生成视频或插画。只有用户同时要求画面、分镜或图片时，才进入图文口播联动模式。

## 默认值

用户没有明确指定时：

- 时长：90 秒。
- 字数：约 330-390 个汉字。
- 画面：用户要求联动时拆为 5-7 个画面；否则只输出完整口播。
- 听众：对主题感兴趣但不具备专业背景的普通用户。
- 语气：有判断、清楚、克制，不喊口号。
- 结尾：用观点收束；不自动要求点赞、关注、评论或转发。

如果原文无法在目标时长内完整表达，只保留一条核心主张和最必要的支撑，不把多个平行主题硬塞进一条视频。

## 结构

### 1. 钩子：前 5-10 秒

用一个具体反差、风险或反常识判断迅速建立问题。钩子必须来自原文真实主张，不制造焦虑，不使用虚假悬念。

优先：

- “一座图书馆可以很热闹，但它的专业价值可能正在消失。”
- “答案越来越容易得到，判断答案是否可靠却越来越难。”

避免：

- “你绝对想不到……”
- “所有人都被骗了……”
- “看完彻底颠覆你的认知……”
- “大家好，今天我们来聊一聊……”

### 2. 建立问题：约 10%-30%

快速解释表象为什么不足以说明真正问题。只保留听众理解核心转折所需的背景。

### 3. 核心判断：约 30%-50%

用一句明确、可复述的话说出视频主张。不要让核心观点直到结尾才出现。

### 4. 递进解释：约 50%-85%

选择 2-3 个最有力的理由、变化或后果。各点之间必须是因果、递进或对比关系，而不是文章目录的压缩版。

### 5. 收束：最后 10%-15%

回到开场矛盾，给出一句有记忆点但不夸大的结论。只有用户明确要求运营话术时，才增加互动问题或行动引导。

## 语言与节奏

- 一句话通常 8-24 个汉字；长句拆开朗读。
- 每 2-4 句形成一个小段落，给主播自然换气位置。
- 多使用具体主语和动作，少用“进行、赋能、打造、全面提升”等空泛表达。
- 专业概念首次出现时，用一句普通语言解释。
- 用“但问题是”“真正的变化是”“换句话说”“所以”推进逻辑。
- 设问后立即回答；整篇通常不超过三个问号。
- 排比最多使用一次，最好放在结尾收束。
- 不逐字朗读屏幕短字，不朗读章节编号和字段名称。
- 不添加原文没有的数据、案例、引语或机构立场。

## 输出格式

### 纯口播

```text
风格：短视频口播
预计时长：
口播字数：

【口播正文】
可以直接朗读的连续正文
```

除非用户要求，不额外输出创作分析、三套钩子或多个版本。

### 图文口播联动

在 `references/voiceover.md` 的逐页格式上增加页面节奏角色：

```text
第 N 页｜时长｜节奏角色：钩子 / 问题 / 判断 / 解释 / 收束
核心观点：
画面设计：
口播：
屏幕短字：
转场：
```

60 秒通常 4-6 页；90 秒通常 5-7 页；3 分钟通常 7-10 页。不要为了页数拆碎同一句话。

## 自检

- 前两句是否已经建立主题和矛盾？
- 核心判断能否用一句话复述？
- 每个解释点是否真的支撑核心判断？
- 删除任一段后，是否会损伤逻辑？如果不会，继续压缩。
- 是否像人在说话，而不是论文摘要或公众号导语？
- 是否存在夸张钩子、虚假悬念或未经来源支持的内容？
- 字数是否匹配目标时长？
- 结尾是否完成观点收束，而不是机械引导关注？
